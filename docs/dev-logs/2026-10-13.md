# 2026-10-13 CSS 转换、动画引擎与面板层级排查记录

> 注：本日志迁移自原 `.workbuddy/memory/2026-10-13.md`，保留当天的排障方法论与关键发现。

## 1. CSS `transition-property` 默认值 + Clutter 动画引擎（提交 `10ba3e0`）

- **发现 1**：St 省略 `transition-property` 时默认值为 `background-color`，而 GTK4 无默认值，导致 `_common.scss` 中大量仅声明 `transition-duration` 的规则在 GTK4 中失效（hover 硬跳变）。
  - 在 `convert-st-css.py` 中以**纯文本输出后处理**方式实现 `inject_transition_property()`（不改主解析循环），同时处理独立 `}` 行和挂在末尾声明上的 `}`，为 16 条规则（后修正到 23 条）补全 `background-color, color, border-color, box-shadow`。
- **发现 2**：GTK4 无内置动画框架，新建 `easing.{h,cpp}` 移植 Clutter cubic-bezier 曲线（含 `ease_out_cubic` 与过冲至 1.0966 的 `ease_out_back`），采用 Newton-Raphson + 二分兜底求解，由 `gtk_widget_add_tick_callback` 驱动。
- **菜单开合两阶段串行**（`quickSettings.js:464 / :500`）：open 先高度补间再淡入，close 先淡出再收起隐藏；关闭期间保持窗口 mapped，回调仅持 window 引用不触碰 `PanelPopover`。

## 2. 二级菜单缺失 `.header` 与 `:checked` 误判更正（提交 `5486f92`）

- 此前曾误判 `:checked` 伪类未生效，后经检查 sassc 产物、转换结果 CSS 与 C++ 状态机确认规则与 `GTK_STATE_FLAG_CHECKED` 均正常，且用户实机确认开启态为蓝色；用 `gtk_style_context_lookup_color` 探测在对照组同样失败，确立“**对照组失败即探针不可信，优先静态对照查证**”的方法论。
- 对照 `quickSettings.js:389` `QuickToggleMenu._init` 定位到真正结构缺口：缺少菜单顶部的 `.header`（24px `.icon` 圆形徽章 + `.title` + `.subtitle`）。新增 `winome_quick_menu_new_full()` 补全该结构，并修正容器类名结构以消除双层圆角边框。

## 3. 固定宽胶囊网格：`max-width` 映射修复（提交 `189ec7a`）

- 对照 `_quick-settings.scss:15` 发现 `.quick-toggle, .quick-toggle-has-menu` 同时设置 `min-width: 12em; max-width: 12em` 构成固定宽网格。
- 原 `convert-st-css.py` 的 `RENAME` 表将 `max-width` 落入 `min-width` 导致上限静默丢失、胶囊按文字伸缩破坏面板视觉节奏。修复 `max-width` / `max-height` 独立映射后，产物 `max-width` 由 0 处恢复至 5 处；同步按 `panel.js:381-405` 对齐快捷开关行顺序。

## 4. 构建期 CSS 覆盖率自检（提交 `f896818`）

- 新增 `tools/check-st-css-coverage.py` 与包装脚本 `tools/convert-then-check.py` 接入 `src/theme/meson.build`，在构建期拦截 `coverage` / `pass-through` / `semantics` / `transitions` 四类静默退化。
- 验证方法：通过**人为注入已知缺陷**发现前两版存在性检查会被其他规则掩盖，遂将 `semantics` 与 `transitions` 均改为数量比较；检查器首次上线即抓出 `inject_transition_property` 漏处理 5 条尾随 `}` 规则的 bug。
